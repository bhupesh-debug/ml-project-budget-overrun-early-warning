*Flag the budget lines most likely to overrun by year-end, at mid-year, with the drivers analysts can act on.*

> **Important:** all data in this repo is synthetic, generated by `src/data_pipeline.py`. Metrics show that the pipeline works end to end; they are not claims about real-world performance. Swap in real data before drawing conclusions.

## Problem
Budget reviewers cannot read every line. This project ranks agency budget lines by overrun risk (final variance above 5%) at a mid-year checkpoint so analyst time goes to the riskiest 20% first.

## Data (synthetic)
3,200 unit-year checkpoints across 4 fiscal years; features include spend versus calendar (`burn_gap`), prior-year variance, overtime share, vacancy rate, vendor spend share, change orders and forecast revisions. Target `overrun` (rate 25%).

## Method
Time-based split (train FY1-3, test FY4). Rule baseline (spending ahead of calendar) vs logistic regression vs gradient boosting; permutation importance for driver explanations.

## Results (test = FY4, 839 rows)
| Model | ROC-AUC | PR-AUC | Recall in top 20% flagged |
|---|---|---|---|
| Burn-gap rule | 0.686 | 0.435 | 36% |
| Logistic regression | 0.906 | 0.777 | 62% |
| Gradient boosting | 0.897 | 0.758 | 60% |

The logistic model slightly beats boosting here because the synthetic generator is close to linear; on real data, compare both. Top drivers: type_non_labor, prior_year_variance_pct, overtime_share, change_orders_ytd. See `reports/feature_importance.png`.
